# 快速开始

从零到 Bot 跑起来，大约 20 分钟。

## 0. 你需要准备什么

| 项 | 说明 |
| --- | --- |
| 一个 VPS | 用来跑 Bot。1 核 1G 就够（它本身几乎不耗资源） |
| Python ≥ 3.10 | VPS 上装 |
| Telegram 账号 | 用来跟 @BotFather 申请 Bot |
| OCI 账号 | 至少一个，每个都要能拿到 API 凭据 |

> 💡 如果你本来就有 OCI 免费实例，**直接拿其中一台跑 Bot 最省事** ——
> 它就在 OCI 内网，API 调用延迟低，而且不额外花钱。

## 1. 申请 Telegram Bot

1. 在 Telegram 里找 **@BotFather**，发 `/newbot`
2. 按提示起名字，拿到 **Token**，形如 `1234567890:AAH...`
3. 再找 **@userinfobot**，给它发任意消息，它会回你的**用户 ID**（一串数字）

这两个值马上要用。**Token 等于 Bot 的密码，泄露了别人就能操作你的云主机。**

## 2. 拿 OCI API 凭据

对**每一个**要管理的 OCI 账号重复以下步骤：

1. 登录 OCI 控制台
2. 右上角头像 → **我的概要文件**
3. 左下角 **API 密钥** → **添加 API 密钥**
4. 选 **生成 API 密钥对** → 下载私钥（`*.pem`）
5. 添加完成后，页面上会显示 **配置文件预览**，长这样：

```ini
[DEFAULT]
user=ocid1.user.oc1..aaaaaaaaEXAMPLEreplacewithyourrealuserocid
fingerprint=00:11:22:33:44:55:66:77:88:99:aa:bb:cc:dd:ee:ff
tenancy=ocid1.tenancy.oc1..aaaaaaaaEXAMPLEreplacewithyourrealtenancyocid
region=ap-singapore-1
key_file=<path to your private keyfile> # TODO
```

前四行就是你要抄进 `accounts.json` 的东西。`key_file` 那行忽略。

（上面的 `fingerprint` 是虚构示例，你控制台里显示的是别的值。）

> 💡 **私钥可以所有账号共用一把。** 在 OCI 里，同一个用户添加多个 API 密钥，
> 或者不同账号用同一份公钥都是允许的。所以 17 个账号配一次私钥就够了。

> ⚠️ **私钥只能下载一次。** 关掉页面就没了。丢了只能删掉重新加一个。

## 3. 安装

### 方式 A：一键部署（推荐，systemd）

```bash
git clone https://github.com/okxnode/oracles.git
cd oracles
sudo ./deploy/install.sh
```

脚本跑完会告诉你接下来改哪两个文件。

### 方式 B：本地手动跑（调试用）

```bash
git clone https://github.com/okxnode/oracles.git
cd oracles
python3 -m venv .venv && . .venv/bin/activate
pip install -e .
```

## 4. 填配置

### 4.1 账号清单

```bash
mkdir -p ~/.oracles && chmod 700 ~/.oracles
cp accounts.example.json ~/.oracles/accounts.json
chmod 600 ~/.oracles/accounts.json
nano ~/.oracles/accounts.json
```

格式：

```json
[
  {
    "index": 1,
    "alias": "新加坡主力",
    "region": "ap-singapore-1",
    "user": "ocid1.user.oc1..aaaa...",
    "fingerprint": "a8:36:29:e7:...",
    "tenancy": "ocid1.tenancy.oc1..aaaa..."
  },
  {
    "index": 2,
    "alias": "备用号",
    "region": "us-ashburn-1",
    "user": "ocid1.user.oc1..bbbb...",
    "fingerprint": "a8:36:29:e7:...",
    "tenancy": "ocid1.tenancy.oc1..bbbb..."
  }
]
```

**字段说明**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `index` | ✅ | 账号序号，唯一，用来在 Bot 里选账号 |
| `region` | ✅ | 形如 `ap-singapore-1` |
| `user` / `fingerprint` / `tenancy` | ✅ | 从控制台抄 |
| `alias` | | 显示名，不填就显示 region |
| `key_file` | | 该账号专用私钥；不填则用全局的 `OCI_API_KEY_FILE` |
| `auth_mode` | | `api_key`（默认）或 `instance_principal` |
| `compartment_id` | | 操作落在哪个 compartment；不填用租户根 |
| `default_shape` | | 默认 `VM.Standard.E2.1.Micro` |
| `default_ssh_key` | | 开新机时注入的公钥文件路径 |

> ⚠️ 字段名写错会**直接报错**而不是静默忽略 —— 这是刻意的，
> 免得你以为配了其实没生效。

### 4.2 环境变量

```bash
cp .env.example .env        # 本地开发
# 或
sudo nano /etc/oracles/oracles.env   # systemd 部署
```

至少要填这两个：

```bash
TELEGRAM_BOT_TOKEN=1234567890:AAH...
TELEGRAM_ALLOWED_USER_IDS=100000001
```

> ⚠️ `TELEGRAM_ALLOWED_USER_IDS` **留空时不响应任何人**。
> 这是安全默认值 —— 一个能删你云主机的 Bot 裸奔在网上，被人搜到就是灾难。

## 5. 自检

**先别急着启动 Bot**，跑一遍自检：

```bash
python -m oracles.cli doctor
```

输出应该是：

```
🩺 环境自检
  配置目录：/etc/oracles
  账号数量：17
  写操作：关闭(DRY-RUN)

正在逐个验证 17 个账号的鉴权…

  ✅ [1] us-sanjose-1             1 个可用域
  ✅ [2] us-sanjose-1             1 个可用域
  ...
结果：17 个正常，0 个失败
```

有失败的话，对照报错处理：

| 报错 | 原因 |
| --- | --- |
| `NotAuthenticated` | 私钥路径错、fingerprint 抄错，或系统时间偏差过大 |
| `NotAuthorizedOrNotFound` | tenancy OCID 抄错 |
| `私钥文件不存在` | `key_file` 路径不对 |
| `config invalid` | 少了某个必填字段 |

## 6. 跑一遍完整自检

```bash
python scripts/selftest.py
```

这个脚本会**只读**演练全部模块：配额、实例、存储桶、安全扫描、计划生成、
写开关拦截、Bot 组装。跑通说明一切都对。

## 7. 启动 Bot

```bash
# systemd
sudo systemctl restart oracles-bot
journalctl -u oracles-bot -f

# 或本地
python -m oracles
```

在 Telegram 里给 Bot 发 `/start`，应该能看到主菜单。

## 8. 熟悉之后再开写权限

出厂是**只读模式**。建议先这样用几天：

1. 点 `/q` 看配额对不对
2. 点 `/i` 看实例列表对不对
3. 点 `/launch 3` 生成创建计划，**检查计划内容**（可用域挑得对不对、镜像对不对）
4. 点 `/terminate` 生成销毁计划，检查是不是你想删的那台
5. 确认无误后，改 `ORACLES_WRITE_ENABLED=true` 并重启

需要销毁实例/删桶时再临时打开 `ORACLES_ALLOW_DESTRUCTIVE=true`，做完立刻关掉。
