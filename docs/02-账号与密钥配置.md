# 账号与密钥配置

## 配置文件在哪

**刻意放在仓库之外。**

```
$ORACLES_HOME/            # 默认 ~/.oracles，生产建议 /etc/oracles
├── accounts.json         # 账号清单（600）
├── oracles.env           # 环境变量与开关（600）
├── keys/
│   └── oci_api_key.pem   # API 私钥（600）
└── backups/              # 改动前的快照（账号清单 + 安全加固规则）
```

`backups/` 里有两类文件，都是 600：

| 文件名 | 什么时候产生 | 保留策略 | 怎么用 |
| --- | --- | --- | --- |
| `accounts-<UTC时间戳>.json` | 删账号 / 改账号字段**之前** | 只留最近 5 份 | 误删了就把文件 `cp` 回 `accounts.json`，再重启服务 |
| `seclist_acc<N>_<列表ID>_<时间戳>.json` | 收紧 22 端口**之前** | 不自动清理 | 含收紧前的完整入站规则，照它在控制台改回去 |

> 备份失败的**降级行为**：账号清单的备份失败**不会**阻断操作（目录不可写就删不了账号
> 太别扭），但会打 WARNING 并在 Telegram 回话里明说「本次不可回滚」。

这个设计直接对应「开源不泄露密钥」这条硬要求：**密钥从一开始就不在工作区里**，
`.gitignore` 只是第二道保险。

改目录位置：

```bash
export ORACLES_HOME=/etc/oracles
```

或写进 `oracles.env`：

```bash
ORACLES_HOME=/etc/oracles
```

## accounts.json

```json
[
  {
    "index": 1,
    "alias": "新加坡主力",
    "region": "ap-singapore-1",
    "user": "ocid1.user.oc1..aaaaaaaaEXAMPLEreplacewithyourrealuserocid",
    "fingerprint": "00:11:22:33:44:55:66:77:88:99:aa:bb:cc:dd:ee:ff",
    "tenancy": "ocid1.tenancy.oc1..aaaaaaaaEXAMPLEreplacewithyourrealtenancyocid"
  }
]
```

（示例里的 `user` / `tenancy` / `fingerprint` 全是**虚构占位值**，
把控制台里显示的真实值替换进去。）

### 全部字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `index` | int | ✅ | — | 账号序号，**必须唯一**，Bot 里用它选账号 |
| `region` | str | ✅ | — | 形如 `ap-singapore-1` |
| `user` | str | ✅* | — | 用户 OCID |
| `fingerprint` | str | ✅* | — | API 密钥指纹 |
| `tenancy` | str | ✅* | — | 租户 OCID |
| `key_file` | str | | 全局私钥 | 该账号专用私钥路径 |
| `alias` | str | | region | 显示名 |
| `auth_mode` | str | | `api_key` | `api_key` 或 `instance_principal` |
| `compartment_id` | str | | tenancy | 操作落在哪个 compartment |
| `default_shape` | str | | `VM.Standard.E2.1.Micro` | 默认实例规格 |
| `default_image_os` | str | | `Canonical Ubuntu` | 默认镜像 OS |
| `default_ssh_key` | str | | `~/.ssh/id_ed25519.pub` | 开新机时注入的公钥 |

\* `auth_mode=api_key` 时必填。

### 校验规则

配置在**启动时一次性全部校验**，并把所有问题一起报出来：

```
❌ 配置错误：
账号配置有问题，请修正后重试：
  · [1] ap-singapore-1: 缺少 fingerprint
  · [3] ap-singapore-1: 私钥文件不存在：/etc/oracles/keys/old.pem
  · [5] ap-singapore-1: auth_mode='magic' 非法
```

几个刻意的设计：

- **未知字段直接报错**，不静默忽略 —— 免得你把 `fingerprint` 拼成 `fingerPrint`
  以后以为配好了，结果一直在用别的值
- **序号重复报错** —— 否则 Bot 里选账号会选错
- **`accounts.json` 不存在时报错并给出复制命令**，而不是创建个空文件让你困惑

## 多账号：私钥怎么放

### 方案 A：所有账号共用一把私钥（推荐）

OCI 允许同一份公钥在多个账号/用户下注册。所以最省事的做法是：

```
/etc/oracles/keys/oci_api_key.pem      # 一把，600
```

在 `oracles.env` 里指定：

```bash
OCI_API_KEY_FILE=/etc/oracles/keys/oci_api_key.pem
```

`accounts.json` 里就**不用写** `key_file`。

### 方案 B：每个账号独立私钥

```json
{ "index": 1, "key_file": "/etc/oracles/keys/acc1.pem", ... },
{ "index": 2, "key_file": "/etc/oracles/keys/acc2.pem", ... }
```

### 权限

私钥必须是 `600`，配置目录 `700`。检查一下：

```bash
ls -l /etc/oracles/keys/
# -rw------- 1 oracles oracles 1704 ... oci_api_key.pem
```

## instance principal（在 OCI 实例上跑 Bot 时用）

如果 Bot 就跑在某个 OCI 实例上，可以让它**不需要私钥文件** —— 用实例身份认证。

### 1. 建动态组

OCI 控制台 → 身份 → **动态组** → 创建：

```
名称：oracles-bot-dg
规则：instance.id = 'ocid1.instance.oc1..你的实例OCID'
```

（或用 compartment 批量匹配：`instance.compartment.id = 'ocid1.compartment...'`）

### 2. 建策略

身份 → **策略** → 创建：

```
允许动态组 oracles-bot-dg 在 tenancy 中管理 instance-family
允许动态组 oracles-bot-dg 在 tenancy 中管理 volume-family
允许动态组 oracles-bot-dg 在 tenancy 中管理 object-family
允许动态组 oracles-bot-dg 在 tenancy 中读取 limits
允许动态组 oracles-bot-dg 在 tenancy 中管理 virtual-network-family
允许动态组 oracles-bot-dg 在 tenancy 中读取 users
允许动态组 oracles-bot-dg 在 tenancy 中使用 customer-secret-keys
```

### 3. 配置

```json
{
  "index": 1,
  "alias": "本机（实例主体）",
  "region": "sa-vinhedo-1",
  "auth_mode": "instance_principal",
  "compartment_id": "ocid1.tenancy.oc1..aaaa..."
}
```

⚠️ `instance_principal` 模式**必须**显式给 `compartment_id` ——
实例元数据里没有租户信息，我们无法推断。

⚠️ 这个模式下**不能签发 S3 密钥** —— 那需要 `user` OCID，实例主体没有。

## 环境变量

### 必填

```bash
TELEGRAM_BOT_TOKEN=1234567890:AAH...        # @BotFather
TELEGRAM_ALLOWED_USER_IDS=100000001,100000002  # @userinfobot 拿 ID
```

### 开关

```bash
ORACLES_WRITE_ENABLED=false       # 关掉 → 所有写操作变 DRY-RUN
ORACLES_ALLOW_DESTRUCTIVE=false   # 关掉 → 销毁/删除类单独再拦一层
```

两者是「与」关系。**平时建议 `DESTRUCTIVE` 保持 false**，
需要删机器时临时打开，做完立刻关掉。

### 可选

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `ORACLES_HOME` | `~/.oracles` | 配置目录 |
| `ORACLES_ACCOUNTS_JSON` | `$ORACLES_HOME/accounts.json` | 账号清单路径 |
| `OCI_API_KEY_FILE` | — | 全局私钥路径 |
| `ORACLES_LOG_LEVEL` | `INFO` | 日志级别 |
| `ORACLES_TIMEOUT` | `120` | 单次 API 超时（秒） |
| `ORACLES_MAX_CONCURRENCY` | `4` | 同时查询的账号数 |
| `ORACLES_SSH_PUBLIC_KEY` | — | 开新机注入的公钥（内联内容） |

### 加载优先级

```
真实环境变量  >  <ORACLES_HOME>/oracles.env  >  仓库根 .env
```

高优先级的不被覆盖。所以本地开发可以放个 `.env`，生产环境用 `oracles.env`，
两者互不干扰。

## 密钥轮换

### 轮换 API 密钥

1. OCI 控制台 → 我的概要文件 → API 密钥 → **添加 API 密钥**（先加新的，别删旧的）
2. 记下新的 `fingerprint`
3. 改 `accounts.json` 里的 `fingerprint` 和 `key_file`
4. 重启：`systemctl restart oracles-bot`
5. 验证：`python -m oracles.cli doctor`
6. 确认无误后再删掉旧密钥

### 轮换 Telegram Bot Token

BotFather → `/mybots` → 选 Bot → API Token → **Revoke current token**。
然后改 `oracles.env` 里的 `TELEGRAM_BOT_TOKEN` 并重启。

### 轮换 S3 兼容密钥

⚠️ **Secret Key 只在创建那一刻返回一次**，之后任何 API 都读不回来。
所以「查看已有密钥」这条路不存在，只能新建一对然后把旧的删掉。

## 常见问题

**Q：一个 tenancy 配两条记录会怎样？**
A：可以。如果它们是同一个租户的不同 user，会**共享同一个对象存储命名空间**
（也就是共用同一份 20 GiB 免费额度）。配额是「账号 + AD」绑定的，但命名空间是
「租户」级的 —— 别按「账号数 × 20 GiB」算总量。

**Q：能管理别人的账号吗？**
A：能，只要你有那个账号的 API 凭据。但请确认你有授权。

**Q：改了 `accounts.json` 要重启吗？**
A：要。配置在启动时一次性加载。

**Q：为什么 `accounts.json` 里有些账号的 region 一样？**
A：不同账号可以在同一区域，它们**互不相干**。配额是按账号绑定的。
