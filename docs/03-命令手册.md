# 命令手册

## 交互方式

两种入口，功能完全等价：

- **按钮菜单** —— 手机上点着用，危险操作天然有两步确认
- **命令** —— 脚本化调用、复制粘贴更快

主菜单：

```
┌────────────────┬────────────────┐
│ 📊 配额总览     │ 🖥 实例         │
├────────────────┼────────────────┤
│ 🪣 存储桶       │ 🧹 审计         │
├────────────────┼────────────────┤
│ 🔒 安全         │ ℹ️ 状态         │
└────────────────┴────────────────┘
```

账号选择器分页显示（每页 8 个），17 个账号是 3 页。

## 命令一览

### 总览

| 命令 | 说明 |
| --- | --- |
| `/start` | 主菜单（账号选择器，直接开始操作） |
| `/help` `/h` | 完整使用帮助 |
| `/status` | 运行状态、开关、配置路径 |
| `/a` `/accounts` | 账号列表 |
| `/cancel` | 取消当前会话所有待确认操作 |

### 配额

| 命令 | 说明 |
| --- | --- |
| `/q` | 全部账号配额总览 |
| `/q 3` | 账号 3 的逐 AD 明细 |

输出示例：

```
📊 共 17 个账号，合计可开 9 台 E2.1.Micro
有余量的账号：
  · [3] ap-singapore-1（ap-singapore-1）→ 2 台，在 AP-SINGAPORE-1-AD-1
  · [13] us-ashburn-1（us-ashburn-1）→ 2 台，在 US-ASHBURN-AD-3
  · [17] eu-frankfurt-1（eu-frankfurt-1）→ 2 台，在 EU-FRANKFURT-1-AD-2
```

单账号明细：

```
【[13] us-ashburn-1】us-ashburn-1
  块存储：已用 0.0 GB / 可用 200.0 GB / 共 200.0 GB
  · US-ASHBURN-AD-1: E2 余 0 核（已用 0） → 可开 0 台
  · US-ASHBURN-AD-2: E2 余 0 核（已用 0） → 可开 0 台
  ✅ US-ASHBURN-AD-3: E2 余 2 核（已用 0） → 可开 2 台
  ⇒ 本账号可开合计：2 台
```

> 注意 `AD-1` 和 `AD-2` 是 **0 核** —— 免费额度只落在 AD-3。
> 这就是为什么不能「取第一个 AD 就开机」。

### 实例

| 命令 | 说明 |
| --- | --- |
| `/i` | 选账号看实例 |
| `/i 3` | 账号 3 的实例列表 |
| `/launch 3` | 创建实例（自动挑 AD） |
| `/start_vm 3 <名称>` | 开机 |
| `/stop_vm 3 <名称>` | 关机 |
| `/reboot 3 <名称>` | 重启 |
| `/terminate 3 <名称>` | 销毁 |

`<名称>` 支持 **OCID** 或**名称的唯一前缀**。匹配到多台会报错让你补全 ——
**绝不猜**，猜错的代价是删错机器。

```
❌ 'e2-ubuntu' 匹配到 3 台实例，请用更精确的名字或 OCID：
   e2-ubuntu-09-1-1789554334、e2-ubuntu-09-2-1789554392、…
```

创建计划的形态：

```
📋 创建实例计划（账号 [3] ap-singapore-1 / ap-singapore-1）
  名称：oracles-3-1789554334
  规格：VM.Standard.E2.1.Micro
  可用域：AP-SINGAPORE-1-AD-1
  镜像：Canonical-Ubuntu-26.04-2026.08.17-0
  子网：subnet-20220122-2117
  引导卷：50 GB
  SSH 公钥：已注入
  ⚠️ 自动挑选了余量最充足的可用域 AP-SINGAPORE-1-AD-1
  ⚠️ 将自动分配公网 IP；若安全列表对 0.0.0.0/0 开放 22 端口，
     该机器会立刻暴露在公网扫描之下（/security 可查）

确认创建吗？
[ ✅ 确认执行 ]
[ ❌ 取消 ]
```

### 存储桶

| 命令 | 说明 |
| --- | --- |
| `/b` | 选账号看桶 |
| `/b 3` | 账号 3 的桶列表 |
| `/obj 3 <桶名>` | 查看桶内对象 |
| `/rmbucket 3 <桶名>` | 删除桶 |
| `/s3key 3` | 签发 S3 兼容密钥 |

桶列表会带上统计和风险提示：

```
【[15] sa-vinhedo-1】共 1 个桶
🪣 example-bucket-20260918（0 个对象，0.000 GiB）
```

如果桶开了版本控制或挂着 PAR，会显示：

```
🪣 mybucket（120 个对象，3.2 GiB，⚠️ 开了版本控制，2 个 PAR）
```

删桶时自动处理三件事：清空对象 → 删 PAR → 删桶。
**PAR 那步不能跳** —— 只要桶上还挂着 PAR 记录（**过期的也算**），
OCI 就会用 `409 PreauthenticatedRequestStillExists` 拒绝删除。

### 审计

| 命令 | 说明 |
| --- | --- |
| `/audit` | 全部账号计费残留审计 |
| `/audit 11` | 指定账号 |

```
💸 计费残留审计：1 个账号，1 项，其中 **1 项正在直接计费**

【[11] eu-marseille-1】
  🔴 未绑定的预留公网 IP：WordPress_public_ip
     129.151.228.145（2022-02-06 创建）—— 预留但未绑定，**直接计费**
```

### 安全

| 命令 | 说明 |
| --- | --- |
| `/security` | 全部账号暴露面扫描 |
| `/security 15` | 指定账号 |
| `/harden <账号> <CIDR> [安全列表名]` | 收紧 22 端口 |

```
🔓 SSH 暴露面扫描：17 个账号，17 个存在全网开放的 22 端口
（提醒：这是 OCI 建 VCN 时自动生成的默认规则，不是手动配的）
  【[11] eu-marseille-1】3 条规则（security_list）
    · wpmdsvcn / Allow Public SSH Connections to WordPress ← 0.0.0.0/0
    · wpmdsvcn / Allow HTTP(S) to WordPress ← 0.0.0.0/0
  【[13] us-ashburn-1】3 条规则，含 1 条 IPv6
```

> ⚠️ 「我没配过安全组」≠「22 端口是关的」。
> `Default Security List` 是建 VCN 时**自动生成**的，默认就开了 22 端口。

收紧：

```
/harden 15 203.0.113.7/32
```

`203.0.113.7/32` 填你自己的固定出口 IP。**一次只改一个安全列表** ——
避免一次性把 17 个账号都改坏。

```
🔒 收紧 22 端口计划
  VCN：default-vcn
  安全列表：Default Security List for default-vcn
  允许来源改为：203.0.113.7/32
  将修改 1 条规则；另外 0 条规则保持原样
    · 第 0 条：0.0.0.0/0 → 203.0.113.7/32
  备份：执行前会把完整规则写入 backups/
```

执行后会打印备份路径。回滚目前**没有一键入口** —— 备份 JSON 里的 `full_ingress_rules`
是收紧前的完整规则，照它在 OCI 控制台改回去即可。

## 按钮交互流程

以「开一台新机」为例：

```
主菜单
  └─ 🖥 实例
       └─ 账号选择器（分页）
            └─ 账号 3
                 └─ 🖥 实例列表  ──┬── 点某台实例 → 操作菜单
                                   ├── ➕ 开新机 → 分步向导
                                   └─ ◀️ 返回
```

### 开新机向导（分步）

```
第 1 步 规格      E2.1.Micro（免费档，固定规格）
                  A1.Flex（自选 OCPU / 内存）
第 2 步 系统      Ubuntu / Oracle Linux / …
第 3 步 磁盘大小
第 4 步 台数
第 5 步 可用域    自动挑有额度的 AD（E2 与 A1 是两套独立限额）
第 6 步 登录方式  🔑 仅 SSH 公钥（默认）
                  👤 设置用户名 + 密码（cloud-init 注入）
                  └─ 选「仅 SSH 公钥」后再问一句：公钥从哪来？
                       · 用我配置的公钥（默认）—— 私钥从不离开你本机
                       · 让 Bot 生成一对新的 —— 生成后立刻把 .key / .pub
                         两个文件发给你，实例菜单里随时可重下
第 7 步 IPv6
汇总确认          ▸ 现在开机（单次：每台试一次，失败就收尾）
                  ▸ 自动抢机 5 / 10 / 20 / 30 秒（后台循环重试，可随时停）
```

**「现在开机」与「自动抢机」的区别是「失败之后怎么办」，不是「开几台」。**
选了 N 台，两种方式都会试着开满 N 台：

| | 单次（现在开机） | 自动抢机 |
| --- | --- | --- |
| 成功一台后 | 接着开下一台 | 接着开下一台 |
| 某台失败后 | **收尾汇报**，不重试 | 睡 N 秒再试，直到满或手动停 |
| 适用 | 额度充足、想马上知道结果 | 容量紧张（ARM 常见），挂着等释放 |

（2026-09-21 修过一个 bug：单次模式在第一台成功后就停了，
选 3 台只开出 1 台 —— 与这里写的「每台只试一次」不符。见踩坑 #61。）

**「让 Bot 生成」只在你明确点它时才发生。** 它是默认**不选**的那一项 ——
因为它会把私钥落到服务器上，还让私钥经过 Telegram。默认保持
「用我配置的公钥」，行为与旧版完全一致。

### 实例操作菜单

菜单会根据当前状态**动态变化**：

| 按钮 | 何时出现 |
| --- | --- |
| 🔌 开机 | 已停止 |
| ⏹ 关机 / 🔄 重启 | 运行中 |
| 🚑 救援控制台 | **仅运行中**（OCI 对停机实例会拒绝，所以停机时不显示） |
| 🔑 下载登录密钥 | **两种状态都有**（读的是 metadata 与服务器上的密钥文件，与实例是否在跑无关） |
| 🗑 销毁 | 始终，且单独一行 + 二次确认 |

点「🔑 下载登录密钥」时，会先拉该实例 metadata 里**实际注入**的
`ssh_authorized_keys`，与本账号存的那把做指纹比对：

- 一致 → 「✅ 核对通过」+ 把 `.key` / `.pub` 发出来
- 不一致 → **明说不匹配**，并列出实例上那把的真实指纹（那台机器可能是
  开机时选了「用我配置的公钥」，Bot 的钥匙根本开不了它）
- 核对不了（OCI 报错）→ **仍然把文件给你**，但说明核对没做成
  —— 扣着不给会让你卡死，静默给会让你以为核对过了

### 硬盘管理菜单

卷列表每行标一个挂载状态，删除按钮**只在「确认没挂」时出现**：

| 标记 | 含义 | 有「🗑 删除卷」吗 |
| --- | --- | --- |
| 🟢 | 已挂载（含 `ATTACHING` / `DETACHING` —— 正在挂上/还没真正脱离都算占着） | **没有** |
| ⚪ | 确认没挂在任何实例上 | **有** |
| ❓ | 挂载状态**没查到**（多半是限流） | **没有** |

点确认后，服务层会**再实时复核一次**挂载关系 —— 两道闸：

- 复核发现已挂载 → 拒绝，并告诉你挂在哪个实例上
- 复核**没做成**（查询失败 / 列不出可用域）→ 也拒绝，并说明「无法确认挂载状态」
  —— 判据是「**确认**它没挂」，不是「没查到它挂着」
- 复核剔除了卷 → 结果里会**分开**说「几块已挂载」和「几块状态没查到」
  （原因不同，合成一句会让你以为复核做过了）

### 关于「返回」

每个界面都有「◀️ 返回」和「🏠 主菜单」。返回是**重新查询**而不是用缓存 ——
所以点「返回列表」看到的是最新状态，不是点进去之前的快照。

## 只读 CLI

Bot 之外还有一个命令行入口，适合脚本化和排查：

```bash
python -m oracles.cli doctor                  # 环境与鉴权自检
python -m oracles.cli accounts                # 账号清单
python -m oracles.cli quota                   # 全部账号配额
python -m oracles.cli quota --account 3       # 指定账号
python -m oracles.cli quota --summary         # 只看汇总
python -m oracles.cli quota --json out.json   # 输出 JSON（给监控用）
python -m oracles.cli instances --account 3
python -m oracles.cli buckets --stats         # 含对象数/体积/PAR
python -m oracles.cli orphans                 # 孤儿卷
python -m oracles.cli audit --account 11      # 计费残留
python -m oracles.cli security                # 安全暴露面
```

**CLI 刻意只读。** 命令行没有确认环节，一按回车就执行，太容易出事。
所有写操作走 Telegram，因为那边有确认流程和写开关。

### 定时巡检示例

```bash
# 每天 9 点把配额快照写到文件，配合监控告警
0 9 * * * ORACLES_HOME=/etc/oracles \
  /opt/oracles/.venv/bin/python -m oracles.cli quota --json \
  /var/log/oracles/quota-$(date +\%F).json
```
